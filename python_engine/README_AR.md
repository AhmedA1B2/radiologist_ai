# Grad-CAM لجميع نماذج Radiologist AI

## الحالة الحالية

يوفر هذا المكوّن محرك تفسير موحّداً لنماذج التخصصات، ويعمل محلياً دون إرسال الصور إلى الإنترنت. تكامل Flutter الحالي مخصص لنسخة Windows Desktop.

يدعم المحرك نوعين شائعين من بنية Keras:
- نماذج CNN التي تحتوي طبقات استخراج الخصائص المكانية داخل النموذج الرئيسي.
- نماذج Transfer Learning التي تحتوي Backbone متداخلاً ورأس تصنيف متتابعاً بعده.

يبحث المحرك عن آخر طبقة ذات خرج مكاني رباعي الأبعاد، ثم يتحقق من أن مسار إعادة بناء التنبؤ يطابق خرج نموذج Keras الأصلي. إذا لم يستطع إثبات هذا التطابق، أو اختلف التصنيف الأعلى بين Keras وTFLite، فإنه يوقف العملية ولا ينشئ خريطة غير موثوقة. قد تحتاج المعماريات ذات الفروع المتعددة أو الطبقات المخصصة إلى إعداد صريح لطبقة Grad-CAM.

## أسماء ملفات Keras

ضع ملفات Keras داخل `python_engine/models/` بالأسماء التالية:

```text
python_engine/models/
  brain_model.keras
  chest_model.keras
  teeth_model.keras
  knee_model.keras
  liver_model.keras
  hand_model.keras
  elbow_model.keras
  finger_model.keras
  forearm_model.keras
  humerus_model.keras
  shoulder_model.keras
  wrist_model.keras
```

يجب أن يقابل كل ملف Keras ملف TFLite وملف تسميات في مجلد التخصص نفسه:

```text
assets/ai_model/chest_model/
  chest_model.tflite
  chest_labels.json
```

ينطبق النمط نفسه على بقية التخصصات. يجب أن يتطابق ترتيب التسميات مع ترتيب مخرجات النموذج. يدعم ملف التسميات قائمة JSON أو كائناً JSON مرتباً، بنفس طريقة قراءة Flutter.

ملفات Keras الكبيرة مستثناة من Git عبر `.gitignore`، لذا ضعها محلياً على جهاز التطوير.

## شروط توافق الإدخال

خط معالجة الصور الحالي في Flutter يرسل RGB بحجم `224×224` وقيم خام `0..255` في Tensor بالشكل:

```text
[1, 224, 224, 3] float32
```

يشترط المحرك أن يتوافق شكل مدخل Keras ومدخل TFLite مع Tensor نفسه. إذا كان أحد نماذجك يتطلب حجماً أو ترتيب قنوات أو تطبيعاً مختلفاً، فلا تغيّر الأبعاد أو القيم عشوائياً؛ يجب أولاً توحيد معالجة Flutter مع إعدادات التدريب والتحويل لذلك النموذج.

يدعم فحص TFLite أنواع float32 وfloat16 والمدخلات الصحيحة ذات معامل quantization معروف. لا يعني ذلك أن كل ملف نموذج يطابق تلقائياً طريقة المعالجة المستخدمة أثناء التدريب؛ المقارنة أثناء التشغيل تتحقق من الفئة الأعلى وتتوقف عند عدم التطابق.

## إعداد Windows

1. ثبّت Python 64-bit بإصدار مدعوم في ملف الإعداد (3.10 إلى 3.13؛ يوصى بـ 3.12).
2. افتح PowerShell في جذر المشروع.
3. شغّل:

```powershell
cd python_engine
.\setup_windows.bat
```

4. تأكد من وجود كل ملفات Keras المطلوبة في مجلد `models`.
5. شغّل التطبيق من جذر مشروع Flutter:

```powershell
cd ..
flutter pub get
flutter run -d windows
```

إذا كنت تستخدم مفسر Python آخر، اضبط `RADIOLOGIST_AI_PYTHON` قبل تشغيل Flutter.

## استخدام Grad-CAM

بعد اكتمال تشخيص تخصص مدعوم، يظهر زر Grad-CAM. ويمكن كذلك تفعيل الخيار:

**إعدادات التطبيق ← إعدادات التقارير ← إرفاق خريطة Grad-CAM في ملف PDF**

عند تفعيل هذا الخيار، يُنشأ التفسير أثناء تجهيز PDF، وتُرفق صورة الإدخال والخريطة المركّبة مع اسم الطبقة المستهدفة وشكل خريطة الخصائص. إذا فشل التحقق أو لم تتوفر ملفات النموذج، يتوقف إنشاء PDF بدلاً من حفظ تقرير يوحي بوجود خريطة صحيحة وهي غير متوفرة.

## فحص النماذج والاختبارات

لفحص ملفات Keras وTFLite والتسميات المتوفرة:

```powershell
cd python_engine
.\.venv\Scripts\python.exe inspect_models.py
```

لاختبار مسارات Grad-CAM على شبكات CNN تجريبية، من جذر المشروع:

```powershell
python -m unittest discover -s python_engine/tests -v
```

كما ينفّذ GitHub Actions اختبارات الشبكات التجريبية على Linux وWindows، إضافة إلى تحليل Flutter، عند تحديث طلب السحب.

## حدود التفسير الطبي

Grad-CAM يوضح مناطق أثّرت في استجابة النموذج للفئة المختارة. لا يثبت وجود إصابة، ولا يرسم حدودها الطبية بدقة، ولا يُعد تشخيصاً مستقلاً. يجب مراجعة صورة الأشعة الأصلية والنتائج بواسطة مختص مؤهل.

هذا تكامل تطويري: Python وTensorFlow وملفات Keras يجب أن تكون متاحة محلياً. لم يتم تضمينها بعد داخل مثبت Windows النهائي.
